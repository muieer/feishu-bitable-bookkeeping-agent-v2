# 飞书自主记账智能体

通过飞书机器人发送自然语言消费消息，智能体依据个人分类知识自主决定是否查询历史、如何处理各笔消费以及何时新增记录。任务进度和最终结果通过飞书交互式卡片反馈。业务行为以本地私有的 [业务规格说明书](knowledges/business_specification.md) 为依据。

实现使用 Python、LangChain Agent（基于 LangGraph）、火山方舟 OpenAI 兼容接口、官方 Python Channel SDK 和官方 `lark-cli`。当前项目的 Python 虚拟环境和依赖已经安装。

## 在当前电脑运行

在终端执行：

```bash
cd feishu-bitable-bookkeeping-agent-v2
.venv/bin/python -m bookkeeping doctor --websocket
.venv/bin/python -m bookkeeping start
```

第一条应用命令只读检查分类知识、真实表字段和长连接，不处理消息。第二条命令保持运行，收到飞书消息后开始记账；按 `Ctrl+C` 停止。

默认读取项目根目录的 `.env`，环境变量可覆盖同名配置。如需选择其他配置文件，使用：

```bash
.venv/bin/python -m bookkeeping --env-file /path/to/custom.env start
```

机器人默认接收私聊。若需要群聊，在配置中设置 `ALLOW_GROUPS=true`，然后在群里 @机器人。`ALLOWED_USER_IDS` 可配置逗号分隔的用户 `open_id`；留空时，用户范围由飞书应用可见范围决定。

## 飞书应用条件

机器人应用需要开启机器人能力，采用长连接接收事件，订阅 `im.message.receive_v1`，并具备对应的消息接收和发送权限，例如 `im:message`、`im:message:send_as_bot`。变更权限或事件配置后，应发布应用版本，使配置生效。官方准备步骤见 [Channel SDK Quickstart](https://github.com/larksuite/channel-sdk-python/blob/main/docs/quickstart.md)。

表格操作使用 `LARK_CLI_IDENTITY` 中配置的身份，默认 `user`。CLI 使用已有登录状态；机器人 SDK 使用 `LARK_APP_ID` 和 `LARK_APP_SECRET`。两者分别负责表格操作与机器人通信，不自动切换身份或重新配置 CLI 认证。

## 新环境安装

需要 Python 3.11 或更高版本，以及已配置身份并可访问目标账本的官方 `lark-cli`。

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

配置格式见 [.env.example](.env.example)。在 `knowledges/` 中提供 `categories.json`、`rules.json`，并准备本地凭证配置后，先执行 `doctor` 检查，再启动机器人。程序启动前会检查实际表字段类型，包括已有的文本字段 `unique_id`。字段缺失或类型不符时停止启动，不自动修改真实表结构。

## 记账行为

- 一条消息可包含多笔消费；符合要求的消费逐笔新增，其他消费说明未入账原因。
- 金额取可以确定的人民币实付金额，使用 `Decimal` 校验正数和两位小数精度。数量、单价或优惠需要计算时，只允许有原文依据的数字和加减乘除。
- 任务执行日按 `TIMEZONE` 计算，默认为 `Asia/Shanghai`。常见相对日期和明确月日由程序核对；省略日期使用该条任务真正开始执行的日期。
- 一级、二级、三级分类必须组成 `knowledges/categories.json` 中的完整合法路径。规则状态和适用边界以 `knowledges/rules.json` 为准；草稿规则不能脱离边界使用，冲突无法消除时不强行分类。
- 消费原文、详情、金额依据和日期依据可追溯到原消息。历史记录只作为分类样本，不能补造用户没有提供的信息。
- 成功卡片展示日期、完整分类、详情和金额。失败及未提交的消费保留原文和原因；已提交但结果无法确认的消费展示为「待核对」。

## 自主决策与权限边界

应用只创建一个自主 Agent，没有预先安排「抽取消费 → 分类 → 查询 → 写入」的固定业务步骤。分类知识在上下文中提供，Agent 可直接新增、先查询历史或直接说明不能入账。

LangChain 的 `create_agent` 负责模型与工具的运行循环；中间件提供每次任务的知识上下文、请求限制、工具串行执行和结束结果校验。业务工具、金额与日期校验、执行日志和卡片反馈分别维护。LangGraph 不额外保存会话或恢复任务，消息去重和中断恢复仍由原有 SQLite 执行日志负责。

纠正计数和同轮结束校验顺序沿用重构前的行为。已知的同轮写入与结束声明边界见 [LangChain 运行边界](docs/architecture.md#langchain-运行边界)。

Agent 的账本工具只有以下两个：

| 工具 | 可执行操作 | 程序限制 |
|---|---|---|
| `query_history` | 查询固定账本中的有限历史样本 | 最多 50 条，只允许消费详情关键词过滤 |
| `add_expenses` | 向固定账本新增消费记录 | 逐笔校验六个消费字段，由程序附加 `unique_id`，逐笔提交 |

工具中固定 CLI 可执行文件、命令、账本、表和字段。模型不能提供 shell 命令、CLI 参数、其他表标识、修改或删除操作。CLI 通过参数数组启动，不经过 shell。结构化最终输出用于声明未提交消费；「已记账」由实际回执和执行日志生成。

架构和异常处理说明见 [设计说明](docs/architecture.md)；工程保障的原因、分层与流程见 [工程保障](docs/engineering-safeguards.md)。

## 防重复与异常结果

SQLite 执行日志按平台 `message_id` 去重，不按消费内容或金额去重。收到新消息时先持久保存，再从 SDK 事件回调返回。相同消息再次投递不会运行 Agent 或新增记录；用户主动发送的新消息仍可记录相同商品和金额。

同一消息内，工具按消费原文在消息中的位置预留提交操作，重叠原文不会再次写入。原文出现多次时，用出现序号区分独立消费。

每笔新消费由程序生成 UUIDv4，并在首次远端写入前，将 ID 和校验通过的消费数据一起保存到现有 SQLite 执行日志。模型不生成或填写 ID。原始写入、核对查询和补写始终复用同一个 ID 与已保存的数据。

写入满足 CLI 的 `ok: true` 和有效 `record_id_list` 即确认成功，不读回表格核验。首次写入时工具无法启动或飞书明确拒绝写入，沿用失败处理。提交后结果不确定时，程序先保存待核对状态，再异步等待 3 秒，使用原身份向指定账本按 `unique_id` 精确查询一次：

- 完整查询只查到一条，且消费日期、详情、金额和全部分类一致：保存飞书行 ID 并确认成功。
- 完整查询没有记录：使用原 ID 和已保存的数据补写一次；仅在补写明确成功时确认成功。
- 查询失败、超时、响应无法解析、结果不完整、内容冲突或查到多条：保留待核对，不补写。
- 补写未能确认成功时保留待核对，包括补写被明确拒绝的情况；不再等待、查询或补写。

同一原文范围再次进入工具时直接复用已有提交结果，不重新运行核对流程。旧执行记录没有 ID 时保留原有处理，不补造 ID 后重写。取消、进程中断或重启不会启动自动补写。原请求延迟完成，仍可能与补写形成重复记录；本方案不提供严格幂等。

卡片发送失败不会改变记账结果。应用每 30 秒补发已保存且尚未送达的最终结果；启动时也会恢复这些通知。停止时等待正在处理的工作最多 10 秒，未完成任务会在下次启动时保留已确认结果，将提交中断的消费标记为待核对。尚未开始的队列消息会在重启后继续处理。

生产执行日志默认保存在 `.runtime/journal.sqlite3`。应保留这个文件及 SQLite 所需的配套文件，以维持重启后的消息去重记录。应用使用进程锁，禁止两个本地进程同时使用同一个执行日志。更换应用或账本时，应配置独立的 `RUNTIME_DIR`。

## 日志和配置

`.runtime/events.jsonl` 记录每次模型请求与响应、工具入参和回执、耗时、消费状态、卡片结果以及异常堆栈，按 10 MB 轮换，保留 3 个历史文件。

日志不记录鉴权请求头，并对已配置凭证、常见认证字段、Bearer 凭证和 WebSocket 连接地址脱敏。配置使用 `SecretStr`；运行目录权限为 `0700`，日志及执行数据库权限为 `0600`。`knowledges/`、`env.txt`、`.env`、虚拟环境和运行数据已加入 `.gitignore`。日志及数据库仍包含消费隐私，应按个人账本数据管理。

默认每条消息最多发出 12 次模型请求、运行 300 秒；模型请求超时 90 秒，CLI 超时 30 秒。默认显式使用 `ARK_REASONING_EFFORT=low`，输出上限 `MODEL_OUTPUT_TOKEN_LIMIT=16384`，可在配置中调整。OpenAI 客户端不隐式重试；真实测试另外在网络层计数，以避免突破用户规定的次数。

查看某条消息保存在本地的结果：

```bash
.venv/bin/python -m bookkeeping show-result om_your_message_id
```

## 验证

本次核对与单次补写功能的完整任务提示词见[开发与独立验收提示词](docs/prompts/unique-id-development-and-acceptance.md)。

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
```

真实模型测试使用 `knowledges/testing/live_cases.json` 中的私有场景和隔离账本，所有消费写入留在测试进程中。每个测试目录有持久请求计数器，最多发出 10 次模型请求，结果校验要求累计数量在 5～10 次范围内。可通过 `--cases-file` 指定其他本地场景文件。

```bash
.venv/bin/python scripts/live_test.py --run-dir .runtime/live-tests/a-new-run
```

复用同一目录时跳过已执行案例；`--retry-failed` 只重测失败案例，计数不会重置。2026-10-14 的测试目录已经累计 10 次请求，不再对它发出请求。

2026-10-15 的 LangChain 重构验证使用 9 次真实模型请求，5 组场景全部通过，所有写入均留在隔离账本。场景覆盖混合消费、个性分类、非消费消息、写入成功/失败/待核对及歧义消费，并检查重复投递不会再次写入。该轮未向真实飞书表新增记录，也未向真实会话发送卡片。验证范围及历史记录见 [公开测试说明](docs/test_report.md)；含个人分类内容的日志与结果仅保留在本地私有目录。

## 常见问题

| 现象 | 检查与处理 |
|---|---|
| `doctor` 无法读取字段 | 在普通终端检查 `lark-cli auth status`，确认所配置身份及账本权限。沙箱中不可访问 macOS 钥匙串时，改在普通终端运行；不要自动降低凭证存储保护。 |
| 长连接握手失败 | 检查机器人应用凭证、长连接事件配置和当前网络；使用 `doctor --websocket` 单独定位。 |
| 消费显示「待核对」 | 检查对应原文在账本中是否存在，程序不会自动再次新增。 |
| 未收到最终卡片 | 查看本地保存结果及 `card_result`、`notification_error` 日志，检查消息权限和会话可达性；恢复连接后应用会补发保存的结果。 |
| 分类不明确 | 查看原文用途和个人规则边界；当前阶段直接说明未入账原因，不自动增加分类或追问。 |
