# 测试与证据管理

公开测试使用人工合成知识库、虚构表 ID、模拟模型和隔离账本，不需要个人凭证，也不会联网调用模型或飞书。分类清单与规则由测试夹具在临时目录生成，避免把个人知识库复制到公开测试文件中。

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
```

真实模型回放从 `knowledges/testing/real_model_classification.json` 和本地个人知识库读取。缺少私有资料时，对应回放测试自动跳过；其他测试仍可运行。

初次实现已通过 73 项本地测试，并验证真实表字段读取、长连接握手和 CLI 新增格式预览。该轮真实模型测试累计发出 10 次请求，4 组完整通过，最后 1 组在总请求上限处未完成模型收尾。修复后的私有模型参数回放通过；回放的结束信号由测试模拟，不能替代完整联网验证。真实表新增及卡片送达尚未做端到端实测。

## 2026-10-15 LangChain 重构验证

重构前的离线基线为 75 项通过。迁移将 Agent 运行机制替换为 LangChain `create_agent` 及中间件，并移除 Pydantic AI 依赖。原有业务提示词、两个账本工具和结束输出校验的业务逻辑保持一致；金额、日期、分类校验、CLI、SQLite 执行日志、卡片和消息通道实现未改动。

新增离线回归覆盖最终输出纠正、纠正次数上限、同轮写入与结束、同轮无效结束、多个账本工具串行执行、30 次工具调用边界、工具参数脱敏、任务上下文隔离，以及实际 LangChain/OpenAI 适配器的模拟 HTTP 请求。模拟 HTTP 验证方舟参数、推理字段回传、HTTP 429/500 不隐式重试，以及网络预算耗尽后保留成功写入结果；这些测试不发出真实 LLM 请求。

首次重构验证的离线测试 100 项通过，包括 98 项公开测试和 2 项私有模型参数回放。独立审查随后发现工具纠正次数错误累计，以及无法解析的工具调用在混合返回时漏计的问题；这一轮测试结果不能单独证明基准行为兼容。

真实模型测试复用本地方舟配置和私有知识库，所有写入均由内存账本接收。5 组场景全部通过，逐组请求数如下：

| 场景 | 请求数 | 结果 |
|---|---:|---|
| 混合消费：多笔有效消费与未入账消费 | 2 | 通过 |
| 个性分类与完整分类路径 | 2 | 通过 |
| 非消费内容 | 1 | 通过 |
| 成功、明确失败和待核对结果 | 3 | 通过 |
| 歧义、缺失信息与不合规消费 | 1 | 通过 |
| 合计 | 9 | 符合 5～10 次限制 |

每组同时检查同一消息重复投递不会再次写入或改变结果。测试未向真实飞书表新增记录，也未向真实会话发送卡片；真实消息通道和卡片送达不在本轮端到端验证范围内。

本轮持久计数与完整响应日志位于 `.runtime/live-tests/langchain-harness-20261015/`。请求计数不重置，不对本轮继续发起模型请求。公开文档只保存场景范围和汇总结果，不复制个人分类、消费原文、真实资源标识或模型响应。

## 2026-10-15 审查修复的离线验证

纠正预算恢复为基准的按工具名、按模型轮次计数；成功轮后清除旧计数，同轮多个同名错误不重复计数。无法解析的 JSON 同样受限制。新增回归覆盖第三次连续失败、混合工具返回、成功后再次纠正、派发前检查预算、未执行调用的用量计数、未知参数拒绝和工具数量限制的可操作反馈。6 个关键复现用例在修复前全部失败，修复后全部通过。

同轮结束输出恢复为先校验、再执行账本工具；多个结束输出沿用首个有效结果。测试明确覆盖这一基准行为，包括同轮 `skipped` 或 `no_consumption` 可能与实际新增结果不一致的既有边界，不把校验移到写入后作为本次迁移的一部分。

修复后离线测试 129 项通过，包括 127 项公开测试和 2 项私有模型参数回放。Ruff、依赖一致性和 Git 差异格式检查通过，两条既有的 Channel SDK 弃用警告仍存在。模块入口与已安装命令入口均可加载帮助信息。

另将既有 5 组场景的 9 个完整模型响应通过模拟 HTTP 逐组回放，得到的报告与已保存结果完全一致，并再次验证消息去重。回放禁止外部网络连接，不产生新的真实模型请求。真实证据目录中 14 个文件的内容哈希保持不变，持久请求总数仍为 9；本轮没有执行真实飞书写入或卡片发送。

包含个人分类路径、规则和模型输出的详细测试报告保存在 `knowledges/testing/test_report.md`。实际请求计数、日志、场景报告和执行数据库保存在 `.runtime/live-tests/`。这两个目录均被 Git 忽略，仅在本地保留。

需要真实模型测试时，先准备本地配置、个人知识库及 `knowledges/testing/live_cases.json`，再运行：

```bash
.venv/bin/python scripts/live_test.py --run-dir .runtime/live-tests/a-new-run
```

每个目录独立持久计数，最多发出 10 次模型请求，最终校验要求数量处于 5～10 次范围。复用目录会保留已有计数；`--retry-failed` 只重测失败案例，不能重置预算。已有测试目录用完预算时，不再继续请求模型。
